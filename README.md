# Органайзер конспектів

Навчальний веб-застосунок (варіант 16) з дисципліни «Програмування веб-застосувань», КПІ ім. Ігоря Сікорського, ФІОТ.
Автор: Печенюк Артур, група ІП-51.

Застосунок дозволяє додавати, редагувати, фільтрувати за предметом і позначати як вивчені конспекти лекцій.

## Технології

- HTML, CSS, JavaScript
- Vue 3 (підключено через CDN)
- IndexedDB — локальне сховище конспектів (база `StudyNotesDB`, сховище `notes`)
- клієнтська маршрутизація на основі `#` (SPA): `#/`, `#/notes/:id`, `#/subject/:subject`
- Node.js (модуль `http`) — сервер з ендпоінтом `/api/notes`

## Запуск

```bash
cd server
npm start
```

Після запуску відкрити http://localhost:3000

## Безпека (практична робота №15)

### 1. XSS (міжсайтовий скриптинг)

**Пошук.** У коді шукалися небезпечні способи вставки HTML: `innerHTML`, `insertAdjacentHTML`, `v-html`.
Вразливе місце: текст конспекту (поле `text`) — великий вільний текст, який вводить користувач
або який приходить з API. Для збереження переносів рядків він виводився через
`v-html` (у Vue це те саме, що `innerHTML`).

**Перевірка до виправлення.** Конспект із текстом

```html
<img src=x onerror="alert('XSS')">
```

після збереження виконав JavaScript: з'явилося вікно `alert('XSS')`, а в DOM з'явився справжній тег `<img>`.

**Виправлення.** Текст конспекту виводиться через інтерполяцію Vue `{{ text }}`.
Вона вставляє дані як `textContent` і екранує спецсимволи, тому HTML показується як звичайний текст і не виконується.
Переноси рядків зберігає CSS-властивість `white-space: pre-line`, тож `v-html` не потрібен.

**Інші місця.** Назва, предмет, дата і дані з `/api/notes` виводяться тільки через `{{ }}` і атрибути `:attr`.
`innerHTML`, `insertAdjacentHTML`, `eval` і `document.write` у коді не використовуються.

### 2. Зберігання даних у браузері

Конспекти можуть містити персональні навчальні дані. Вони зберігаються в IndexedDB лише на пристрої користувача
й нікуди не передаються. Проте браузерні сховища не шифруються і не мають терміну дії.
Доступ до них має будь-який скрипт на сторінці, тому XSS дозволив би їх викрасти.

Висновок:

- **localStorage** для конспектів недоречний. Після міграції в IndexedDB (практикум 11) стара копія `studyNotes`
  тепер видаляється (`removeLegacyLocalStorage`). У localStorage лишається тільки службовий прапорець
  `migratedToIndexedDB=true` без персональних даних.
- **IndexedDB** — прийнятне місце для конспектів у навчальному застосунку без облікових записів.
  Дані зберігаються, доки користувач сам їх не видалить (кнопка «Видалити» або очищення даних сайту в браузері).
- Паролі, токени та інші секрети в браузерних сховищах **не зберігаються**.
- Не варто працювати із застосунком на чужому або спільному комп'ютері: дані залишаються в браузері.

### 3. Секрети в коді

У клієнтському коді та на сервері немає API-ключів, токенів і паролів.
Застосунок звертається тільки до власного ендпоінта `/api/notes`, який не потребує ключа.
Якщо ключ знадобиться, він має зберігатися на сервері (змінні середовища, файл `.env`, доданий у `.gitignore`), а не у фронтенді.

### 4. Розгортання з HTTPS

Обрано **GitHub Pages**: сайт роздається тільки через HTTPS (опція *Enforce HTTPS*), без налаштування сертифікатів,
а код уже зберігається на GitHub. HTTPS шифрує трафік і не дає підмінити `script.js` або Vue з CDN по дорозі.
GitHub Pages віддає лише статичні файли, тому для сервера `/api/notes` у разі потреби
можна використати платформу з HTTPS для Node.js (наприклад, Vercel або Render).
